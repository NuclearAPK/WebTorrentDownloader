# Онлайн-просмотр видео в браузере — спецификация

**Дата:** 2026-05-20
**Версия проекта на момент дизайна:** 1.0.8
**Целевая версия:** 1.1.0 (первая итерация дорожной карты)

## Цель

Добавить возможность смотреть видеофайлы прямо в веб-интерфейсе сервиса средствами браузера — без необходимости скачивать файл или кастить на DLNA-устройство. Поддерживаются:

1. Скачанные файлы из каталога `downloads`.
2. Файлы из активных торрентов (просмотр во время загрузки).

## Контекст и предпосылки

Backend проекта уже содержит инфраструктуру стриминга, разработанную для DLNA:

- `GET /api/stream/:filename` — HTTP-стрим скачанного файла с поддержкой Range.
- `GET /api/stream/torrent/:infoHash/:fileIndex` — стрим из активного торрента.
- `GET /api/transcode/:filename` — транскодирование через FFmpeg с пресетами `low` / `medium` / `high` / `original`.
- `transcoder.needsTranscoding(filename)` — проверка по расширению (`.mkv`, `.avi`, `.wmv`, `.webm`, `.flv`, `.mov`, `.m4v`).
- `streamingServer.isMediaFile(filename)` — определение видео/аудио по MIME.

Все стрим-эндпоинты сейчас открытые (без `authMiddleware`). Это сделано намеренно для совместимости с DLNA-устройствами, которые не отправляют Bearer-токены. В рамках этой задачи политика **не меняется** — веб-плеер будет использовать те же открытые эндпоинты.

## Принятые решения

| # | Решение | Обоснование |
|---|---------|-------------|
| 1 | Отдельный «экран» просмотра (SPA-режим во весь экран), а не модальное окно | Лучший фокус, согласованно с типичным UX видеоплееров |
| 2 | Источник — все видеофайлы (скачанные + из активных торрентов) | `streamTorrent` уже реализован, бэкенд готов |
| 3 | Авто-транскод через FFmpeg для несовместимых форматов + ручной выбор качества | Закрывает MKV/AVI/MOV «из коробки», пользователь может регулировать нагрузку |
| 4 | Стрим-эндпоинты остаются открытыми | Сервис работает в локальной сети, DLNA требует открытости |
| 5 | Нативный HTML5 `<video>`-плеер без сторонних библиотек | Минимум кода, нулевые зависимости, легко обновлять |

## Архитектура

### Backend (server.js + новый модуль)

**Новый эндпоинт:** `POST /api/watch/resolve` — `authMiddleware`.

Принимает на вход одну из двух форм:

```json
{ "type": "file", "filename": "movie.mkv", "quality": "medium" }
```
или
```json
{ "type": "torrent", "infoHash": "abc...", "fileIndex": 2, "quality": "medium" }
```

Возвращает:

```json
{
  "url": "/api/transcode/movie.mkv?quality=medium",
  "mimeType": "video/mp4",
  "isTranscoding": true,
  "size": 1234567890,
  "title": "movie.mkv",
  "duration": 5400,
  "qualities": ["low", "medium", "high", "original"]
}
```

Логика подбора URL переиспользует существующий код из `/api/dlna/cast` (server.js:648–698): если `transcoder.needsTranscoding(filename) || quality !== 'original'` — даём transcode-URL, иначе — обычный stream-URL. Длительность (`duration`) запрашивается через `transcoder.getMediaInfo()` для скачанных файлов; для торрентов в первой итерации возвращается `null` (получим её позже).

**Эндпоинт `/api/media/files`:** в первой итерации **не трогаем**. Клиент уже знает список скачанных файлов (через существующий `/api/files`) и активных торрентов (через `/api/torrents`), кнопку «Смотреть» добавляем при рендере этих списков на стороне клиента, определяя видеоформат по расширению. Решение о транскоде принимает сервер при вызове `/api/watch/resolve`.

**Эндпоинт `/api/transcode/:filename`:** уже принимает параметр `?quality=low|medium|high|original` (по умолчанию `medium`). Не требует изменений.

### Frontend (public/index.html + public/app.js + public/style.css)

**Структура `index.html`:**

Добавляется новая `<section id="watchSection" class="watch-section" style="display: none;">` после секции `dlna-section`. Контейнер `#appSection` и `#watchSection` — переключаемые «вьюхи» SPA. Внутри `watchSection`:

```html
<section id="watchSection" class="watch-section" style="display: none;">
  <header class="watch-header">
    <button id="watchBack" class="btn-secondary">← К списку</button>
    <h2 id="watchTitle"></h2>
    <div class="watch-quality">
      <label for="qualitySelect">Качество:</label>
      <select id="qualitySelect">
        <option value="original">Оригинал</option>
        <option value="high">Высокое (1080p)</option>
        <option value="medium" selected>Среднее (720p)</option>
        <option value="low">Низкое (480p)</option>
      </select>
    </div>
  </header>
  <video id="watchPlayer" controls preload="metadata"></video>
  <div id="watchStatus" class="watch-status"></div>
</section>
```

**Логика `app.js`:**

1. Состояние `currentView` (`'library'` или `'watch'`) — функция `setView(view)` переключает `display` секций.
2. Новые функции:
   - `openWatch({type, filename, infoHash, fileIndex})` — вызывает `POST /api/watch/resolve`, заполняет заголовок, ставит `<video>.src`, переключает вьюху, восстанавливает позицию из `localStorage`.
   - `changeQuality(preset)` — запоминает `currentTime`, запрашивает новый resolve, ставит новый `src`, выставляет `currentTime` обратно после `loadedmetadata`.
   - `closeWatch()` — сохраняет позицию в `localStorage`, останавливает `<video>`, возвращает вьюху.
3. Кнопка «Смотреть» (`▶ Смотреть`) добавляется:
   - в карточку каждого скачанного видеофайла (рендер `filesList`),
   - в каждую строку файла внутри развёрнутого торрента (рендер `torrent-files-list`), если файл — видео и `selected !== false`.
4. Сохранение позиции:
   - Ключ — `watch:pos:${filename}` или `watch:pos:${infoHash}:${fileIndex}`.
   - Запись — на событиях `pause`, `seeked`, `beforeunload` и при закрытии плеера.
   - Чтение — после `loadedmetadata`; если позиция > 5 сек и < `duration - 30`, показываем уведомление «Продолжить с N:NN» с действием.

**CSS:**

- Секция `.watch-section` — занимает основную область, `<video>` — `width: 100%; max-height: calc(100vh - 200px); background: #000`.
- Заголовок `.watch-header` — flex, кнопка «Назад» слева, селектор качества справа.
- Совместимость с тёмной темой (используем существующие CSS-переменные).

### Поток данных

```
User clicks "Смотреть"
   │
   ▼
app.js: openWatch({filename})
   │
   ▼
POST /api/watch/resolve {type, filename, quality}  ──── Bearer JWT
   │
   ▼
server.js: вычисляет URL стрима, возвращает метаданные
   │
   ▼
app.js: <video>.src = streamUrl  ──── open endpoint, без JWT
   │
   ▼
Browser: HTTP GET с Range-запросами ──► streamingServer.streamFile / transcoder.handleTranscodeRequest
   │
   ▼
Stream pipe в <video>
```

### Граничные случаи и обработка ошибок

| Случай | Поведение |
|--------|-----------|
| `<video>` событие `error` | Показать сообщение в `#watchStatus` + кнопка «Попробовать в другом качестве» |
| `resolve` вернул 404 | Toast-уведомление «Файл не найден», возврат к списку |
| `resolve` вернул 401 | Перенаправить на форму логина (тот же обработчик, что используется в проекте) |
| Файл из активного торрента, который был удалён | `streamTorrent` вернёт 404 — toast и возврат |
| Стрим прервался (сеть упала) | Браузер сам пытается возобновить через Range; если фатально — `error`-обработчик |
| FFmpeg не установлен | `/api/transcode/check` уже есть — при первом открытии вьюхи делаем `GET /api/transcode/check`, при `available: false` скрываем пункты транскода |
| Перемотка вперёд в несакчанный участок торрента | WebTorrent обработает приоритизацию; UI показывает «Буферизация» через событие `waiting` |
| Несколько вкладок плеера | Допускается, каждый запрос — независимый стрим. Транскод порождает отдельный ffmpeg-процесс на запрос — нужно убедиться, что transcoder.js это корректно обрабатывает |

### Совместимость и форматы

| Контейнер/кодек | Действие |
|------------------|---------|
| `.mp4` (H.264 + AAC) | Прямой стрим |
| `.webm` | Прямой стрим |
| `.mkv`, `.avi`, `.wmv`, `.flv`, `.mov`, `.m4v` | Транскод в MP4 H.264/AAC |
| Прочие (e.g. `.ts`, `.mpg`) | Транскод (с расширением списка `supportedInputFormats` в transcoder.js) |

## Что НЕ входит в эту итерацию

- Выбор аудиодорожки и субтитров (видны через `getMediaInfo`, но UI не строим).
- HLS-стриминг (повышает качество перемотки в транскоде, но требует переписать transcoder.js).
- Сторонние плееры (Plyr, Video.js).
- Картинка-в-картинке, кастомные шорткаты сверх нативных `<video>`.
- Длительность для файлов из активных торрентов (потребует `ffprobe` потокового чтения).
- Защита стрим-эндпоинтов токеном (вынесено в отдельный возможный апгрейд).
- Кнопка «Отправить на DLNA» прямо из плеера (легко добавить позже).

## Тестирование

В проекте нет автоматических тестов (зафиксировано в CLAUDE.md). Ручная QA-матрица:

1. Скачанный `.mp4` H.264 → прямой стрим, перемотка работает.
2. Скачанный `.mkv` → автотранскод, играет в браузере.
3. Активный торрент (видео ещё не докачано) → стрим из торрента, перемотка вперёд показывает буферизацию.
4. Переключение качества во время воспроизведения → продолжает с того же места.
5. Закрытие вьюхи → позиция сохраняется; повторное открытие предлагает продолжить.
6. Поломанный файл → graceful error в `#watchStatus`.
7. Отсутствие FFmpeg → пункты транскода в селекторе недоступны/скрыты.

## Дорожная карта (вторая и третья итерации)

- **v1.2.0** — Plyr поверх `<video>` для красивых контролов и шорткатов; кнопка «Отправить на DLNA» из плеера.
- **v1.3.0** — Транскод в HLS-сегменты (опционально, если перемотка в живом транскоде окажется проблемой); выбор аудиодорожки и субтитров.

## Критерии приёмки первой итерации

- Кнопка «Смотреть» появляется рядом с каждым видеофайлом (и в скачанных, и в активных торрентах).
- Клик открывает «экран» просмотра, видео начинает воспроизводиться.
- Перемотка работает для нативных форматов.
- Селектор качества переключает поток без потери позиции.
- Кнопка «← К списку» возвращает в основной интерфейс, позиция сохраняется.
- Версия в `package.json` поднята до `1.1.0`, изменения внесены в `CHANGELOG.md`.
